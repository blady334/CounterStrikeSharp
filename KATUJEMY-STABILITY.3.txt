CALLBACK DISPATCH — adapted PR #1496
https://github.com/roflmuffin/CounterStrikeSharp/pull/1496
Head: f2ac76d18133ae7e7472735ac80545ffebe40117
Cache MethodInvoker and parameter types instead of reflecting on every callback.
Use MethodInvoker in listeners and allocate ScriptContext string cleanup queues
only when a string actually needs unmanaged storage.
Keep independent callback ownership from stability.1 and capability cleanup from stability.2.
Adaptation: parameter types come from the delegate Invoke signature, not its target
MethodInfo. Closed static and open instance delegates can have different signatures.
Both cases fail with the original PR implementation and pass after adaptation.
Use a weak-key invoker cache so a collectible delegate type can be unloaded.
The PR's in-game benchmark changes were replaced with an offline benchmark that
uses the actual reverse-P/Invoke entry and requires no fake engine entity pointers.

PROFILING — adapted PR #1208
https://github.com/roflmuffin/CounterStrikeSharp/pull/1208
Head: 229d83de10d5820834a25d14475fd5a3ba18d938
Eight VProf budget scopes: game frame, pre/post entity think, player think,
CheckTransmit, generic script callbacks and pre/post game-event callbacks.
Pre/post scopes wrap current KHook callback loops; old event-manager code is not restored.
CheckTransmit is static in the current code, so its name must be a literal.
ScriptCallback also uses a fixed label rather than a pointer into a temporary owner's
string. Profiling is grouped by operation, not by individual plugin or callback name.
Current SDK enables VProf; the scopes use the profiler's existing activation state.
No additional console logging or automatic profiler recording was introduced.
The expected VProf EnterScopeInternalBudgetFlags<0,false> symbol is already used
by the supplied libserver.so and libengine2.so. Full native linking is checked in CI.
