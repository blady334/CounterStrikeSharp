CounterStrikeSharp 1.0.380-katujemy-stability.6 — 2026-11-17

Base: stability.5, 8b2c266c6be08e5417e3aae9fd64c25158838428.
Scope: callback dispatch allocation and immutable listener snapshots.

- Native callback lists are built lazily once after registration changes, then
  shared across dispatches. Each snapshot retains its callback owner. Published
  lists stay immutable; shared tombstones disable removed registrations at once,
  including removal/re-addition and plugin release during nested dispatch.
  Empty lists retain no allocated list. Engine-thread usage rules are unchanged.
- Managed callbacks with 0–4 arguments use fixed-arity MethodInvoker overloads;
  larger signatures retain a per-invocation array. There is no shared argument
  buffer or pooled object array retaining plugin references. Delegate Invoke
  signatures, diagnostic attribution, completion and exception handling remain.
- Added arity/order and nested callback tests, retained-snapshot mutation coverage,
  and opt-in offline callback/timer microbenchmarks. Existing unload, timers,
  collectible context, buffer bounds and lifecycle tests are retained.

Five samples, 100,000 calls/sample, .NET 10, tiered compilation disabled equally

These are dispatch measurements, not production FPS or tick-time claims.

Timer scheduling is unchanged. A separate optimized benchmark of the actual
current RunFrame with stub callbacks measures roughly 9 us/pass for 1000 idle
repeat timers and 10 us/pass when all are due. It excludes actual plugin bodies,
managed callback dispatch, timer churn and game work. No alternative scheduler
has been implemented or validated. Profile a live workload before redesigning
timer ordering/cancellation. --benchmark modes disable sanitizers; normal safety
harness modes keep ASan+UBSan on Linux.
