CAPABILITIES RELOAD (redesign of the problem reported in PR #1082)
https://github.com/roflmuffin/CounterStrikeSharp/pull/1082
Reviewed upstream head: 0d2de242e2f8e45ad8612a6a607217c81d306fcd
The original patch is NOT merged. Existing two-argument registration APIs stay intact.
Registrations are owned by the collectible AssemblyLoadContext of the supplier's
method/target, with contextual reflection as the fallback for shared helpers during Load.
Manual unload and failed Load remove that generation's exact typed registrations.
AssemblyLoadContext.Unloading also cleans up. Another provider of the same name survives.
Cleanup runs even if Plugin.Unload, Dispose or service-scope disposal throws.
Late callbacks cannot register suppliers again after their owner was unloaded.
Weak ownership records and cleared removal lists do not pin an unloaded context.
Get snapshots the provider under a lock, then invokes user code outside that lock.
An already running provider invocation is allowed to finish.
As before, a capability name that has never been registered throws on Get; a name
whose providers were removed returns default. Public API compatibility is preserved.
Suppliers entirely in non-collectible shared assemblies, registered outside any
plugin contextual-reflection scope, cannot be attributed to a plugin by this API.
Use a supplier lambda declared in the owning plugin for those runtime registrations.
